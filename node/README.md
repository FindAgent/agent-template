# Node code agent (Node 22/24)

A complete FindAgent code agent: a crates.io health check served as an MCP server over stdio, with the
six entry tools, a result panel, and every platform rule met. Read the [root README](../README.md) for the
Agent Plugins model, the checklist and the pitfalls. This file is the Node specifics.

## Layout

| Path | What |
|---|---|
| `src/mcp/server.ts` | the stdio server: tools, the panel resource, elicitation, logging |
| `src/mcp/tools.ts` | the seven tools, the `needs_input` shapes, the panel binding |
| `src/check.ts`, `signals.ts`, `crates.ts`, `http.ts` | the check itself (the part you replace) |
| `panel/` | panel source (HTML, CSS, JS) built into `ui/index.html` by `scripts/build-panel.mjs` |
| `findagent.json` | the contract; `skills[]` is generated by `pnpm sync:manifest` |
| `manifest.json` | DXT manifest, generated, for hosts that read one |
| `test/` | unit, contract, stdio (real MCP client), panel (real Chromium) and platform-check tests |

## Commands

```
pnpm_config_strict_dep_builds=false pnpm install --frozen-lockfile   # PowerShell: $env:pnpm_config_strict_dep_builds="false"; pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test                 # builds, then runs every test (needs Chromium: pnpm exec playwright install chromium)
pnpm check:generated      # findagent.json, manifest.json and ui/index.html are current
pnpm check:platform       # the platform rules (run after a build)
pnpm live                 # the built server over stdio against the real crates.io
```

pnpm 11 refuses install scripts it has not been told about (esbuild's, here) and fails with
`ERR_PNPM_IGNORED_BUILDS`. Run the install once with `pnpm_config_strict_dep_builds=false` set, as above;
every later `pnpm <script>` then works. (The `--config.strictDepBuilds=false` flag is not enough: pnpm's
own pre-run check re-installs without it.) pnpm also writes a local `pnpm-workspace.yaml`: it is
git-ignored on purpose, because a tracked one makes the platform build fail. Never commit it.

## Making it yours

1. Replace `src/crates.ts`, `signals.ts` and `check.ts` with your logic; keep `http.ts` as the only code
   that touches the network, and keep redirects off.
2. Update `TOOLS` in `src/mcp/tools.ts`, then run `pnpm build && pnpm sync:manifest` so `skills[]` follows.
3. Change `allowed_hosts` in `findagent.json` to exactly the hosts you call.
4. Edit the panel in `panel/` and run `pnpm build`; commit the rebuilt `ui/index.html`.
5. `pnpm test && pnpm check:platform`, then submit as described in the root README.

`build_command` is `npm run build`: the sandbox installs with npm from `package.json`, and the build
script only runs `tsc` and the panel build.
