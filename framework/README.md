# Framework-style code agent (Python 3.13)

A complete [FindAgent](https://findagent.cloud) code agent for the case "I already have an agent written with an agent
framework". It shows the wrapper pattern: the agent's loop sits behind an MCP server that exposes the platform's six
entry tools. Read the [root README](../README.md) for the model, the checklist and the pitfalls. This file is the
specifics of this variant.

## What this is, and what it is not

**This variant does not import an agent framework.** It carries a tiny local agent loop (`framework_agent/agent_loop.py`:
`Agent`, `function_tool`, `Runner`, a trace) with a deterministic planner and no language model. The reasons are
practical: the sandbox installs exact pins with a binary wheel and nothing else, framework SDKs move fast and pull
large dependency trees, and an agent the platform serves should give a complete, repeatable answer without a model.
Wrapping the OpenAI Agents SDK, LangChain or LangGraph, CrewAI or LlamaIndex was not run here; the mapping below is
the pattern, and you pin and test the framework yourself.

The example agent turns commit subjects into release notes: `classify_commits` and `render_notes` are the two tools the
loop calls, `triage_commits` is the one capability tool the server exposes.

## Layout

| Path | What |
|---|---|
| `server.py` | entrypoint (`findagent.json` `entrypoint`) |
| `framework_agent/agent_loop.py` | the loop: agent, function tools, runner, turn limit, trace. Replace it with a framework |
| `framework_agent/triage.py` | the domain tools and the planner (the part you replace) |
| `framework_agent/tools.py` | the seven MCP tools, the `needs_input` shapes and the dispatcher |
| `framework_agent/mcp_server.py` | the stdio server; logs go to stderr |
| `findagent.json` | the contract; `skills[]` is generated by `scripts/sync_manifest.py` |
| `requirements.txt` | what the sandbox installs (exact pins); `requirements-dev.txt` adds the dev tools |
| `tests/` | the loop, the dispatcher, the contract and a real stdio MCP client run |

## Mapping to a framework

| This variant | In a framework |
|---|---|
| `Agent(name, instructions, tools, planner)` | the framework's agent (`Agent` in the OpenAI Agents SDK, the compiled graph or agent executor in LangChain and LangGraph, `Agent` in CrewAI) |
| `@function_tool` | the framework's tool decorator (`function_tool`, `@tool`, `@tool`) |
| `Runner.run_sync(agent, goal)` | `Runner.run_sync`, `agent.invoke`, `crew.kickoff` |
| `TriagePlanner.next_step` | the model call that picks the next tool |
| `RunResult.turns` | the framework's trace or steps |

To wrap a real framework agent: keep `tools.py` and `mcp_server.py`; in `_run` call the framework instead of
`Runner.run_sync(TRIAGE_AGENT, ...)`; map the framework's exceptions to a classified `ok: false` result; add the framework
and every transitive dependency to `requirements.txt` as exact pins, and run `python scripts/sync_manifest.py`.
Three things to settle before you do:

- **A model needs a key.** A hosted code agent cannot hold your key; if the loop calls a language model the buyer must supply theirs through a credential slot (`credential_slots` in `findagent.json`, bound to the provider's exact host, which must also be in `allowed_hosts`). Keep a deterministic path that answers without a model if you can.
- **No compiled dependencies.** The build is `pip install -r requirements.txt --target <deps>`. A framework that needs a native wheel for Linux and Python 3.13 must have one on PyPI.
- **Egress is default-deny.** Every host the framework calls goes in `allowed_hosts`, and nothing else is reachable.

## Commands

```
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
ruff check . && ruff format --check .
mypy framework_agent server.py scripts
pytest
python scripts/sync_manifest.py --check
npx --yes @findagent/cli@0.4.2 check .            # the platform's own whole-repo check, offline
```

## Make it yours

1. Replace `triage.py` (and `agent_loop.py` if you use a framework) with your agent. Keep the six entry tools and the `needs_input` shapes.
2. Rename in `pyproject.toml` and `findagent.json`; set `allowed_hosts` to exactly the hosts your code calls.
3. Run `python scripts/sync_manifest.py` after changing the tools, and the gates above.
4. Never `print()` to stdout: it belongs to the MCP stream.

Nothing in this repository submits or publishes anything for you. Submit at <https://findagent.cloud/submit> through the
GitHub door, or over MCP with `findagent_create_code_draft`.
